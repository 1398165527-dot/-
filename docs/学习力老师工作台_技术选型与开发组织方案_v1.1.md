## 二、目标技术架构

### 2.1 分层与系统主权

为避免多工具并存导致数据割裂，明确**唯一系统主权**原则：

- **核心业务数据层（系统主权所在）**：Supabase Postgres（Neon 为二选一候选）承载第四章全部逻辑实体——学员、报名、课次、考勤、课时账、财务、服务记录索引、文档索引、画像版本、模块偏好、提醒、用量。任何外部工具中的内容都以 document_ref / 关联记录回挂到核心实体。
- **接入与调度层**：Cloudflare 承载前端托管、定时任务（提醒生成、采集调度）与备份对象存储；Supabase Edge Functions 承载需要紧邻数据库的服务端逻辑。两者分工在 W01 验证后细化，避免重复计固定费。
- **协作与采集层（非主权层）**：企业微信（客户沟通）、飞书（咨询记录整理与日程提醒）、钉钉 AI 听记（录音转写）、Notion（知识库）均为业务层的协作/采集界面；其中的客户资料、咨询内容、知识条目进入工作台时按 document_ref 登记「原件在哪里 / 工作台保存什么 / AI 可使用什么」三层信息。
- **设计与内容层**：musepool 定风格方向，Canva 出品牌物料，image_generation 出插画配图，interactive-research-report 出经营/复盘报告页。
- **研发支撑**：GitHub 管代码与任务，scholar 支撑课程研发的理论检索。

### 2.2 与 v0.3 三层模型的对应

| v0.3 要求 | v1.1 落实 |
|---|---|
| 合同原件不默认上传 | 原件仍在老师指定位置（本地/云文档）；工作台仅存索引；企业微信微盘/飞书云文档若用于存放，同样只登记索引并逐项核实访问控制 |
| 受限学员资料边界 | 飞书中的咨询记录属受限资料：默认不进 AI 公开文案上下文，跨工具引用须经老师选择摘要范围 |
| AI 可使用范围逐份设置 | document_ref 的 ai_scope 字段覆盖来自飞书/Notion/钉钉的每一份文档 |

## 三、指定工具的能力验证清单（修订版 W01）

W01 目标由「候选选型」改为「指定工具链能力验证 + 缺口补齐」。每项验证使用匿名样例，结果记入决策记录。

### 3.1 Supabase / Neon（数据层二选一验证）
- Supabase 验证项：行级安全（按 owner_teacher_id 隔离，验收剧本 H）、定点数金额、事务与冲销写入、Edge Functions 定时触发、存储桶权限、备份/恢复、用量与价格（待报价）。
- Neon 验证项：分支用于开发/测试隔离、迁移工具链、与所选框架的适配、备份保留与价格（待报价）。
- 决策点：若 Supabase 行级安全与函数调度满足，则 Supabase 为主、Neon 作开发分支环境或退出；若 Supabase 关键项不满足，则 Neon 主数据库 + 自建服务层。二者不重复承担生产主库，避免固定费双倍计入。

### 3.2 Cloudflare（部署与调度）
- 验证项：前端托管、Workers 定时触发（关闭界面后运行提醒/采集）、对象存储（备份落点）、日志与重试、费用（待报价）。
- **国内可达性专项**：Cloudflare 在国内的访问稳定性与备案要求需实测确认；若结论不适合面向国内老师日常使用，备选为境内云托管（待报价），此项是 v1.1 新增的待确认风险。

### 3.3 GitHub（工程管理）
- 验证项：私有仓库、分支保护、PR 评审流、Actions CI（构建/测试）、Issues 跟踪 W01—W10 工作包。
- 注意：国内网络访问稳定性问题，必要时配置镜像或境内代码托管备选（待确认）。

### 3.4 wecom-unified（企业微信，客户沟通）
- 该套件已覆盖：通讯录查找、日程、会议、待办、微盘、邮件、消息发送（文本/Markdown/图片/文件等）、在线文档与表格。
- 仍需逐项核实（v0.3 红线不变）：**客户联系（外部联系人）接口、会话存档开通条件与授权、历史会话范围、消息发送给客户的通道限制、凭据存放与费用**。套件能力不等于企业管理员已授权；未核实前，客户沟通走「工作台生成草稿 → 老师在企业微信确认发送 → 回执登记」的过渡闭环。
- 验收锚点：剧本 A（首咨跟进）、剧本 I（外发确认）。

### 3.5 lark（飞书，咨询记录 + 日程提醒）
- 指定用途落实：咨询记录以飞书文档承载（文字、手写识别结果、录音转写文本三种输入均可粘贴整理），日程与提醒用飞书日历/任务。
- 验证项：文档读写与权限分组、日历提醒的可靠触达、与工作台的关联方式（文档链接回挂 service_index）。
- 边界：飞书中的咨询原文属受限学员资料，默认不对 AI 开放；工作台只存索引与老师选定摘要；家长反馈版仍须老师确认后交付。
- 备选说明：飞书妙记也具备音视频转写能力，但本轮录音转写主路径已指定钉钉 AI 听记（D-13），妙记仅作备选，不重复采购。

### 3.6 dws（钉钉，AI 听记整理录音）
- 落实路径：老师提供录音文件 → 钉钉 AI 听记转写 → 转写文本进入 S3 Skill 整理流程 → 老师核对 → 归档索引回挂工作台。
- 红线（v0.3 不变）：工具可用 ≠ 已获录音授权；录音须基于老师与家长的既有告知同意，专门录音许可流程系统仍属延期事项；转写文本中无法辨认内容标「待核对」，不得补成事实。

### 3.7 Notion（知识库）
- 落实：公共专业资料与老师个人知识的收集、整理、版本管理；检索结果按任务引用进服务与内容创作。
- 验证项：数据库/页面结构、权限分区（公共/个人/受限三分区映射）、导出能力。
- **风险标注**：Notion 为境外服务，国内访问稳定性与数据存放合规需评估；受限学员资料**不放入 Notion**，只放公共与个人知识。

### 3.8 scholar（课程研发理论检索）
- 落实：研发项目（沙龙小班/学习力营/教育产品）立项时的理论依据检索，检索结果（标题、作者、年份、引用）作为 knowledge 条目登记来源，供课程大纲与内容创作引用；不虚构文献。

### 3.9 设计四件套（musepool / Canva / image_generation / interactive-research-report）
- musepool：工作台整体风格方向把关，落实文档 05 的九组模块配色与统一暖白基底。
- Canva：对外品牌物料（海报、课程介绍），套用品牌模板批量产出。
- image_generation：界面空状态插画、内容配图；产出须符合模块主题色。
- interactive-research-report：把经营统计、阶段复盘结果做成可交互报告页，供老师个人复盘与（经脱敏后）对外展示；涉学员数据时必须匿名化。

## 八、跨工具数据流转示例（以一次咨询服务为例）

用于检验各工具分工是否闭环，全部使用虚构样例：

1. 家长在企业微信发来咨询意向 → 老师确认后，工作台在 Supabase 建立 lead（渠道=企业微信，过渡期为人工登记，接入后自动同步）。
2. 老师用 lark 日历排首次咨询 09:30—10:15 → 工作台登记 session（精确到分钟，小时刻度显示）→ Cloudflare 定时任务生成到期提醒 → 工作台首页与 lark 任务双通道触达。
3. 到场签到、核销按 Supabase 中的考勤与课时账规则处理（五状态分离，见 v1.0 第四章）。
4. 课后录音经 dws 钉钉 AI 听记转为文本 → 文本进入 S3 Skill 整理（lark 文档承载整理稿）→ 老师核对 → 工作台登记 service_index + document_ref（原件在 lark 文档、工作台存索引、AI 可用范围为老师选定摘要）。
5. 家长反馈版经老师确认后，通过企业微信发送（接入前为老师手动发送并回执登记），状态推进到「已交付」。
6. 涉及的理论参考经 scholar 检索登记来源进入 Notion 知识库；后续研发项目引用时回链来源。
7. 全过程的 token、转写分钟、存储增量记入 Supabase 用量表，供 P25 成本估算。

任何一环的工具不可用，按 v1.0 的过渡口径降级（如手工录入、人工发送），业务状态机不变。

## 九、环境与账号规划

1. 环境划分：开发 / 验证 / 正式三套配置可区分，凭据与真实数据不混用；Neon 分支或 Supabase 分支用于开发验证（二选一随 D-02/D-04 结论）。
2. 账号主体：GitHub 组织、Supabase 组织、Cloudflare 账户、飞书/钉钉/企业微信的企业主体与管理员身份需在 W01 登记（谁持有、谁授权、凭据存放位置）；凭据一律存安全配置，不进入代码、页面、Skill 或 AI 输入。
3. 权限最小化：每个工具只开通本方案用得到的权限范围；企业微信与飞书的管理员授权逐项记录授权人与日期。
4. 匿名化纪律：开发、验证环境一律使用虚构样例；真实学员数据只在正式环境且完成权限评审后进入。
