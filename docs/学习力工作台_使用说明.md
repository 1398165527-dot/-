# 学习力工作台 · 使用说明（验证版 v1.0）

> 本说明对应「学习力工作台」验证版（前端单机版）。
> 目的：帮助你在小范围验证时快速上手，理解每个页面能做什么、背后的业务规则是什么、当前版本有哪些边界。

---

## 〇、开始前必读（三个重要事实）

1. **示例数据全部为虚构。** 学员「林小舟 / 陈一诺 / 王思远」、学校、联系人、金额、成绩、合同路径等均为演示数据，不对应任何真实个人或机构。
2. **数据只保存在你当前这台电脑的当前浏览器里**（localStorage，存储键 `xxl-workbench-v1`）。换浏览器、换电脑、清除浏览器数据，数据都会丢失，也不会跨设备同步。这是验证版的设计，不是故障。
3. **AI 内容是“建议草稿”，不是自动执行。** 本版中学员画像更新等 AI 功能为本地模拟生成，必须人工点击「采纳」才会写入；未采纳不产生任何数据变更。正式接入 AI 后，这一“人工确认”原则保持不变。

## 一、快速上手（5 分钟走一遍主流程）

按下面顺序点一遍，就能体验完整业务闭环：

1. **今日工作台**：看一眼“下一场服务”——今天 09:30—10:15，林小舟第 5 次咨询。
2. **课表与日程**：点进这条课次，做三件事——先填「课前准备」，到点后点「签到」，课后点「标记完成」。
   - 签到时会自动核销 1 课时（因为林小舟的报名产品设定为“签到核销”）。
   - 重复点签到不会重复扣课时（幂等设计，可亲自验证）。
3. **课次详情里点「整理记录」**：写一条服务记录，先「保存并归档」，再「标记反馈已交付」。注意：归档和反馈交付是两个独立状态。
4. **客户与学员 → 林小舟 → 课时与报名**：看课时账的变化——多了一条「核销」流水，余额自动重算。
5. **客户与学员 → 林小舟 → 人生档案（在“人生与事业”模块）**：点「生成 AI 更新建议」，再点「采纳」——档案从 v2 升到 v3，旧版本保留在历史里。
6. **任务与时间**：把一条任务拖入/设为某个四象限；注意「到期提醒」和「四象限」是两套独立维度，互不影响。
7. **设置与接入 → 数据管理**：点「导出 JSON」把当前数据存到本地；点「恢复示例数据」随时重置。

## 三、核心业务规则（验证时重点体验的设计）

这些规则是 v0.3 文档中已确认的方向，代码层面已强制实现：

### 1. 签到 / 服务完成 / 课时核销 / 记录归档 / 反馈交付 —— 五个状态互相独立

- **签到**：标记学员到课。**重复签到不重复扣课时**（幂等）。
- **服务完成**：课次本身上完，点「标记完成」。会顺带生成“课后跟进”待办（去重，不会生成两条）。
- **课时核销**：只有报名时快照里的核销规则为「签到核销」的产品，签到才扣课时；「服务完成核销」的产品在完成时扣；「不自动核销」的（如首次咨询）永远不自动扣。
- **记录归档**：服务记录写完后手动归档。
- **反馈交付**：记录发给家长/学员后手动标记。
- 五个状态可以处于任意组合，页面徽标分别显示，互不冒充。

### 2. 课时账是“只增不改”的流水账

- 余额永远 = 报名课时 + Σ（核销/补回/冲销流水），**不存余额字段，每次实时重算**。
- 签到错了怎么办？用「更正」：出勤→请假/缺勤，会自动生成一条「补回」流水，原流水保留，历史可追溯。
- 退费生成「冲销」流水，不删除任何历史。

### 3. 报名快照：改价不影响旧报名

- 报名那一刻，产品的**课时数、单价、核销规则被复制进报名记录（快照）**。
- 之后产品改价（产品页里“升版”），旧报名仍按快照结算，新报名用新版本。

### 4. 任务双维度：到期提醒 ≠ 四象限

- A 维度「到期提醒」：按截止时间自动进今日工作台的提醒区。
- B 维度「四象限」：重要/紧急的手动分类。
- 两者正交：一条任务可以没有到期时间但在“重要不紧急”象限；「等待中」的任务默认不进象限。

### 5. 12 次服务是三个口径，不是一个数

- **计划次数**（报名快照）、**已完成课次**（课次状态）、**已归档记录**（记录状态）分别统计。
- 推论：没存记录 ≠ 没上课；一份记录 ≠ 多扣一课。学员详情页有常驻提示。

### 6. 合同三层信息分离

- ① 原件在哪里（如 `D:\合同\...` 本地路径或网盘链接，一键复制）；
- ② 工作台保存什么（合同编号、金额、日期等结构化摘要）；
- ③ AI 可使用什么（脱敏后的最小信息）。
- 工作台**不存储合同原件**。

### 7. 金额用“分”存储，缺考 ≠ 0 分

- 所有金额内部以整数分存储，界面显示为元，避免浮点误差。
- 成绩录入中「缺考」与 0 分是两个不同状态，缺考不参与均分。

### 8. 内容模块：无指标不标爆款

- 内容流水线：收集 → 筛选 → 创作中 → 待发布 → 已发布。
- 「爆款」标记必须有真实数据指标支撑，验证版未接入平台数据，因此不出现爆款标。
- 点「发布」会弹确认框，二次确认后才流转到已发布。

### 9. 模块“隐藏”不是“删除”

- 设置里可以把暂时不用的模块从导航隐藏，数据完好保留，随时恢复显示。

## 四、各页面操作要点

### 今日工作台
- 三个「今日重点」槽位：点击空白槽位从任务中选，点已占用槽位可更换。
- 「随手记」：写下即存，自动进入「知识与灵感 → 灵感」。
- 提醒区汇总四类：课次临近、任务到期、等待中超期、反馈未交付。

### 课表与日程
- 「新建课次」：选学员、产品、时间；与现有课次时间重叠时会弹出冲突警告（分钟级判断），可继续保存或改时间。
- 课次详情：课前准备 → 签到 → 更正（出勤/请假/缺勤）→ 标记完成 → 整理记录，一个弹窗走完。

### 客户与学员
- 学员阶段：潜在 → 已咨询 → 已报名 → 服务中 → 暂停/结案，随时切换。
- 「转介绍」字段：王思远的档案里标注了“转介绍自林小舟”。
- 记录来源支持三种标记：文字 / 手写识别 / 录音转写（后两种对应 W01 待接入的手写 OCR 与 AI 听记，本版仅作来源标记）。

### 产品与报名
- 升版：改价或改课时必须升版本号，旧报名不受影响。
- 报名：选学员+产品后自动生成快照，初始流水「报名」入账。

### 财务
- 收入/支出登记；每笔可「冲销」（生成反向记录，原记录保留并标红“已冲销”）。
- 顶部四卡：本月收入、本月支出、待确认、净额。

### 人生与事业
- 学员档案按版本管理。「生成 AI 更新建议」基于已有记录模拟产出草稿；「采纳」才生成新版本，「弃用」不留痕。

### 知识与灵感
- 灵感：一键转化为「任务」「知识条目」或「研发需求」。
- 知识库三区：方法论 / 案例素材 / 学术理论（预留 scholar 检索入口，验证版未接入）。
- 研发项目：里程碑勾选推进。

### 设置与接入
- **Skill 中心 S1–S4**：展示四个 AI 技能（记录整理、画像更新、周复盘、内容选题）的定位与状态——本版为本地模拟，正式模型与价格**待报价、待接入**。
- **外部接入状态**：Supabase、Cloudflare、企业微信、飞书、钉钉、Notion 等全部标注为「待核实 / 待接入」，与实施方案 W01 验证清单一一对应。
- **数据管理**：导出 JSON（备份/迁移用）、恢复示例数据（一键重置）。

## 五、常见问题

**Q：我录的数据刷新后还在吗？**
A：在同一浏览器里在；清缓存、换浏览器、换设备就没了。重要数据请及时用「导出 JSON」备份。

**Q：签错到了怎么办？**
A：课次详情里用「更正」，系统保留原记录并自动生成「补回」课时流水。

**Q：为什么这条记录显示“已归档”但不能改状态？**
A：归档与反馈交付是独立动作，分别操作；两者都完成才算记录闭环。

**Q：可以删掉示例学员吗？**
A：验证版未开放删除（业务上学员档案也不建议物理删除，结案即可）。重置请用「恢复示例数据」。

**Q：AI 功能是真的吗？**
A：画像更新为本地规则模拟，用于验证交互流程；真实模型接入是 W01 之后的工作，成本与选型见《技术选型与开发组织方案 v1.1》。

## 六、小范围验证建议

建议验证清单（每项都能在工作台中直接操作验证）：

- [ ] 签到幂等：对同一学员重复签到，课时只扣一次
- [ ] 更正补回：出勤→缺勤后，课时账出现「补回」，余额恢复
- [ ] 快照隔离：产品升版改价后，旧报名仍按原价显示
- [ ] 五状态分离：一条课次的签到/完成/核销/归档/交付互不影响
- [ ] 任务双轨：到期提醒与四象限独立设置
- [ ] 三口径：计划 12 次 / 已完成 4 次 / 已归档 2 份同时成立不矛盾
- [ ] 冲销不删账：财务冲销后原记录仍可见
- [ ] 导出/重置：导出 JSON 后重置，数据回到种子状态

发现问题请记录：操作路径 → 期望 → 实际，反馈到 GitHub Issues。
